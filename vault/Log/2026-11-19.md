
## Terminal shell selection

- Added **New Terminal With…** and **Default Shell** to the command palette. A one-off selection opens a new tab. Setting a default writes `[terminal] shell` and applies to new terminals in the current client.
- Existing `[agents.shell]` definitions still supply the default and its arguments when `[terminal] shell` is empty. Windows resolution checks for a usable `SHELL` or native Git Bash/MSYS before falling back to Windows PowerShell.
- The Windows GNU target and its tests compiled with `cargo check --workspace --tests --locked --target x86_64-pc-windows-gnu`. Verified the terminal picker and saved configuration in a real Linux PTY, including preservation of the existing config comment. The website build, Rust formatting check and workspace Clippy passed.
- The full workspace suite passed with `cargo test --workspace --locked`.

### Mixed shells in tabs and splits

- Added a clickable shell dropdown beside the new-tab button and split shell choices in the palette and the tab and session context menus.
- The client now detects the launching shell before consulting `SHELL`, unless an explicit shell preference is configured. Linux reads process ancestry from procfs, macOS uses `ps`, and Windows uses a process snapshot and resolves the executable path.
- Verified a real Linux TUI launched by Bash with a conflicting `SHELL`, opened the dropdown, and ran a separate shell beside Bash. Workspace tests, formatting, Clippy, the website build, and cross-target checks for Windows x86_64 and macOS ARM64 passed. Native Windows and macOS runtime testing remains open.
