# 2026-11-07

## v0.5.8: sidebar buttons ignored clicks (0.5.7 regression)

| | |
|---|---|
| Symptom | User report: "+ new" (and "menu") in the classic sidebar did nothing on click. |
| Cause | 0.5.7 added a whole-area `SidebarHit::SpacesList` rect (wheel target) of `room*2` rows. With fewer spaces than `room`, it extended over the buttons row, was pushed to `sidebar_hits` before `New`/`Menu`, and `on_mouse` took the first match. Tree sidebar unaffected (buttons recorded first). |
| Fix | `App::on_mouse` prefers any specific hit over the `SpacesList`/`AgentsList` catch-alls, regardless of record order. |
| Evidence | New test `render::tests::sidebar_buttons_take_clicks_when_spaces_do_not_fill_the_list` failed before the fix, passes after; full `cargo test --workspace`, clippy `-D warnings`, fmt clean. |

Lesson: catch-all hit areas must not depend on push order.
