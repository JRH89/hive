## Windows/macOS TUI testing (v0.5.10)
User report: Hive was "a nightmare" in Windows Terminal/PowerShell. Until now only the daemon and CLI were tested on Windows ([[Phase 10 - Windows]]); the TUI never was.

| Change | Evidence |
|---|---|
| New `crates/hive-cli/tests/tui.rs`: runs the real TUI in a PTY (ConPTY on Windows) against a private daemon, reads the screen through vt100, drives it with terminal bytes: start-up, typing, Leader c, Leader v split, help, resize, Backspace editing, Leader q detach, sessions survive, reattach restores the screen | CI run 43630650454 green on ubuntu, macos-15, windows-2022, windows-11-arm |
| **Bug: Ctrl+Space did nothing on Windows.** The console decodes NUL through the keyboard layout, so it isn't `Ctrl+Space`; the next key went to the shell. `keys::normalize` folds `Null`/`Ctrl+@`/`Ctrl+2` into Ctrl+Space before leader matching | First CI run 43630095185: Windows screen showed `PS ...> c` and no `#2`; passes after the fix. Unit test `every_nul_form_becomes_ctrl_space` |
| **Bug: 16 colours in Windows Terminal** (sets neither TERM nor COLORTERM). `WT_SESSION` now means truecolor | `windows_terminal_gets_truecolor` (e2e, all OSes) and `windows_terminal_is_truecolor_without_term_or_colorterm` |
| Test bug: Ubuntu's `/bin/sh` is dash (no history), so an Up-arrow recall step failed only in CI; replaced with Backspace editing | run 43630095185 Linux job |
| macOS: Option isn't Alt by default in Terminal/iTerm2, so the Alt chords don't fire. Documented (getting started, user guide); Leader keys unaffected | docs only |
